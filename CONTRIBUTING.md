# Contributing

## Commits and pull requests

Use [Conventional Commits](https://www.conventionalcommits.org/) for commit messages and pull request titles, in the form `type(scope): description`; omit the scope when it adds no useful context. Use types such as `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `build`, `ci` and `chore`. Use `chore(deps)` for production dependency updates and `chore(dev-deps)` for development-only dependency updates.

Keep descriptions concise and imperative, and state the change's purpose. Keep commits logically scoped and avoid unnecessary intermediate commits. A pull request title should describe the completed change, not implementation steps. Its description should summarize the change, explain relevant design decisions and list the verification performed.
